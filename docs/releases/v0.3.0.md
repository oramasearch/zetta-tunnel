# zetta-tunnel v0.3.0

**Released 2026-11-15.** Two security fixes: a rotated or withdrawn credential now ends the sessions
it authorized, and an ingress host can require the edge's client certificate. Also the MIT licence,
the contribution rules and a software bill of materials. Same binary and image,
`docker.io/oramasearch/zetta-tunnel:v0.3.0`; every role of [v0.2.0](v0.2.0.md) is unchanged unless
listed here. No flag, file format or projection field is removed or made required, so a v0.2.0
configuration runs unchanged.

## What it includes

| Change | Roles | Pull request |
|---|---|---|
| **A rotated or withdrawn credential ends the sessions it authorized.** On every credential refresh (startup, every two seconds, `SIGHUP`) the role fingerprints the certificate, key and CA files with SHA-256, following symlinks. When they change, every open session is closed with the audit reason `credentials_changed`, and new sessions use the new files. When they cannot be read or do not load, every session is closed with `credentials_unavailable` and new traffic is refused until valid files return. Before, a session kept the TLS context it started with, so a withdrawn certificate kept working for as long as its connection stayed open | peer, relay, endpoint, client | #49 |
| **An ingress host can require the edge's client certificate.** A host in the projection may name `client_ca`, a PEM CA file. That host's TLS then requires a client certificate signed by it (the same check as ingress-nginx's `auth-tls`, used for an edge's authenticated origin pulls), and refuses a caller without one. `CF-*` and `True-Client-IP` request headers reach the backend only from a caller that presented a verified client certificate; from anyone else they are removed, so a caller that reaches the gateway directly cannot claim a client address | ingress | #50 |
| **The egress test fixture works on macOS.** It no longer calls itself until the gateway's resolver thread runs out of stack, so every `egress_*` test passes on a Mac (test-only; nothing shipped changes) | egress (tests) | #46 |
| **Open-source licensing.** The MIT `LICENSE` and `COPYRIGHT` (OramaSearch, Inc.), an `SPDX-License-Identifier` line in every source file (`tools/spdx-headers.py`), `THIRD_PARTY_LICENSES` (`tools/third-party-licenses.py`), and a reproducible SBOM in SPDX 2.3 and CycloneDX (`sbom.spdx.json`, `sbom.cdx.json`, `tools/sbom.py`) | all | #53 |
| **Contribution and security policy.** `CONTRIBUTING.md`, the Contributor License Agreement (`CLA.md`), `CODE_OF_CONDUCT.md` and `SECURITY.md` (private reports to security@orama.com) | all | #51, #52, #53 |
| **Build scripts take their target as input.** `tools/build-image.sh` and `tools/prove-mesh-linux.sh` require `KCTX` (the kubectl context of the cluster that runs BuildKit) and `IMAGE_REPOSITORY`; `BUILDKIT_NAMESPACE` defaults to `buildkit`, and the anonymous Docker Hub check that the repository is private runs only with `REQUIRE_PRIVATE_REPOSITORY=1` | build | #52 |

Issues closed by these: #34, #37, #42.

## Upgrading

- **Credential rotation now closes sessions.** Renewing a certificate (cert-manager, or replacing the
  mounted files) closes every open session of that role once; clients reconnect with the new
  credentials. Expect one reconnect per renewal.
- **Edge headers on the ingress.** A host that does not name `client_ca` no longer passes `CF-*` or
  `True-Client-IP` to its backend. A backend that reads the edge's client address or country from
  those headers must be on a host with `client_ca`.
- **Building the image:** pass `KCTX` and `IMAGE_REPOSITORY` to `tools/build-image.sh`, as
  [Image and releases](../image.md) shows.

## What it does not include

Everything v0.2.0 listed is still not included: tunnel clients for macOS on Intel, Linux arm64 and
Windows (#26); audit delivery into the workspace Zetta; usage records and common metrics (#18);
QUIC.

## Known issues

Security-relevant first.

1. **The mesh role is not ready for several production workloads on one node.** Isolation and
   per-workload limits between workloads that share a node land in a later release (#29, #30).
2. **An enrolled mesh workload needs the operator's matching projection** (`pod_uid` and
   `network_namespace_inode`, from v0.2.0); until the operator ships it, an enrolled workload is
   refused (fail closed).
3. **The relay sees a tunnel's plaintext** (as in v0.1.0): run application TLS inside the tunnel
   where the relay must not see the bytes.
4. **Per-source limits share one quota behind a NAT or proxy** that hides client addresses.
5. **The peer audit does not record why an established session ended.** A peer writes its record at
   setup, so `credentials_changed` and `credentials_unavailable` appear only for sessions still in
   setup; established sessions are closed all the same (#55). The tunnel roles record the reason in
   `session_end`.
6. **The macOS client is not signed or notarized.**
7. **The relay's address changes** when its last grant ends.
8. **The privileged Linux mesh proof** (`mesh_linux_fail_closed`) was not run for this release.

## Where it has run

Before this release, only in tests. This release has not been deployed to a cluster.
