# Security policy

## Reporting a vulnerability

Please report security vulnerabilities privately, by email to **security@orama.com**. Do not open
a public issue, pull request or discussion for a vulnerability.

Include what you can of:

- the affected project, version or commit;
- what an attacker can do, and what they need first (an account, network access, a crafted file);
- steps or a proof of concept that reproduce it;
- any fix or mitigation you suggest.

You may encrypt your report; ask at the same address for a key.

## What we commit to

| Step | Within |
|---|---|
| We acknowledge your report | 2 business days |
| We confirm the issue, give it a severity and tell you our plan | 7 days |
| We release a fix, or agree a coordinated disclosure date with you | 90 days |

We keep you informed until it is resolved. We credit you in the release notes and the advisory
unless you ask us not to.

## Supported versions

Security fixes go to the latest release. Older releases are not maintained; upgrade to receive
fixes.

## Scope

This policy covers the code in this repository. A vulnerability in a dependency should go to that
project too; tell us as well if it affects us.
